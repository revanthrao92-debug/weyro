2. Architectural Layer Specifications
📱 Mobile Client Architecture (src/)
  • Expo SDK 57: React Native 0.81, React Compiler, TypeScript ~6.0.3.
  • Hardware SecureStore: JWT pairs stored in iOS Keychain & Android KeyStore.
  • Automatic 401 Interceptor: Silently refreshes expired access tokens.
  • Offline Mutation Queue: Stores mutations locally; retries with exponential backoff and UUID Idempotency-Key.
  • Decomposed Screens: All screens maintained under 220 lines.
⚙️ Backend Modular Monolith (apps/api/)
  • NestJS 11 on Node 22 LTS: Domain-isolated modules (Auth, Damage, Quotes, Payments, Uploads, Chat, Tasks, Health).
  • Strict Input Gating: Zod schemas with .strict() strip unknown keys.
  • Deterministic State Machines: Guarded status flows for Requests, Quotations, and Bookings.
  • Rate Limiting: 5 req/min on Login/Register; 20 req/min on Uploads.
  • Health & OpenAPI: Liveness/Readiness probes and Swagger at /api/docs.
📦 Shared Monorepo Packages (packages/)
  • @weyro/api-contracts: Pure TypeScript types shared between client and server.
  • @weyro/validation: Single source of truth for runtime Zod input validation schemas.
  • @weyro/database: Prisma ORM, PostGIS spatial queries, and baseline SQL migrations.
☁️ Cloud & Database Layer (Supabase ap-south-1)
  • PostgreSQL 17: Deployed in Mumbai with PostGIS 3.3.7 spatial support.
  • Supavisor Pooling: Transaction pooling on port 6543; direct DDL on port 5432.
  • Presigned S3 Uploads: Direct-to-bucket media uploads bypassing API server memory.
  • Cloudflare CDN: Global caching and delivery for vehicle photos.

4. Issues Discovered and Remediated During Audit
✅ 1. Route Path Discrepancies Resolved

The mobile app was requesting /quotations/bookings and /damage-requests/feed, whereas controllers had registered /bookings and /damage-requests/broadcast-feed. Added NestJS multi-path route decorators (@Get(['bookings', 'quotations/bookings']) and @Get(['broadcast-feed', 'feed'])) ensuring 100% route alignment with zero 404s.

✅ 2. Vehicle Auto-Resolution for Mobile Requests

Mobile damage requests broadcasted vehicle attributes (vehicleMake, vehicleModel, vehicleYear) rather than database IDs. Enhanced CreateServiceRequestSchema and service logic to auto-find or upsert the vehicle for the customer seamlessly.

✅ 3. Rate Limit Mobile UX Feedback

Added dedicated HTTP 429 handlers in auth.tsx and DamagePhotoUploader.tsx. Users exceeding rate limits receive helpful guidance ("Please wait 60 seconds") instead of raw error exceptions.
